# Проверки версии 1.1

Проверено 13 ноября 2026 года в отдельной среде с PostgreSQL 16.

- `go test -v ./...` с TEST_DATABASE_URL: 14 тестов, включая миграции на чистой
  схеме, повторный запуск, состояния Telegram FSM, устаревшую кнопку и /cancel.
- `go vet ./...`: без замечаний.
- `go build -mod=readonly`: успешная сборка backend.
- `npm run build`: TypeScript и production-сборка frontend проходят.
- `scripts/acceptance.py`: 10 сквозных сценариев, включая все 75 сочетаний
  scope/period/metric рейтинга, JSON/CSV, ручную публикацию без ИИ, синонимы,
  потерю консенсуса, экспертное решение, права преподавателя, аудио и Range.
- Повтор ответа возвращает исходную квитанцию, включая бонус цели, и не меняет XP.
- Первый запуск: демозадание выдаётся до повторного запуска API.
- Chromium/Playwright: отсутствующий email вызывает постоянное сообщение
  в форме; вход администратора и панель подготовки аудио/переводов открываются.
- Все объявленные REST-маршруты перечислены в OpenAPI.
- Docker-образы backend и frontend собираются. Проверена цепочка nginx →
  backend от непривилегированного пользователя → чистая PostgreSQL, включая миграции.

Настоящие Telegram Bot API и внешний ИИ не проверялись с рабочими ключами.
Для Telegram используется тестовый HTTP-транспорт; ручной путь не требует ИИ.
Тестовые голоса не являются подтверждённым носителями корпусом.
Нагрузочное тестирование и реальная экспертная оценка переводов не проводились.

Браузер проверялся через Vite; Docker frontend использует такой же `/api/v1`
через nginx. Docker-сборки выполняются с дополнительным CA среды как временным
BuildKit secret: сертификат не включается в распространяемый образ.

После разделения слоёв повторены проверки на новой чистой БД: 14 Go-тестов
(включая архитектурный и тесты сервиса входа), go vet, сборка cmd/server
и все 10 сценариев scripts/acceptance.py. Драйвер и HTTP-контекст не входят
в интерфейсы сервисов. Номера миграций сохранены.
