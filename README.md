# ТелемКүпер — Башкирская языковая школа

Веб-платформа и Telegram-бот для проверки парных переводов. Пользователи
подтверждают или исправляют предложения, получают XP, выполняют ежедневные
цели и пополняют экспортируемый корпус. Требования и границы реализации:
[docs/requirements.md](docs/requirements.md).

## Быстрый старт

Нужны Docker и Docker Compose. При первой сборке нужен доступ к реестрам образов,
npm и Go Modules.

```sh
cp .env.example .env
# Задайте собственные POSTGRES_PASSWORD, JWT_SECRET и ADMIN_PASSWORD.
docker compose up --build -d
```

- Сайт: http://localhost:5173 (также работает по адресу сервера).
- API через сайт: http://localhost:5173/api/v1.
- Прямой API: http://localhost:8080/api/v1.
- Проверка доступности: http://localhost:8080/health.
- Контракт: [docs/openapi.yaml](docs/openapi.yaml).

Frontend обращается к `/api/v1` на своём домене. Nginx и Vite проксируют запросы
в backend: адрес localhost не зашит в браузерную сборку. Для отдельного домена API
можно задать VITE_API_URL при сборке и список разрешённых WEB_ORIGIN через запятую.

JWT_SECRET — не менее 32 байт, пароль начального администратора — 12–72 байта.
Не публикуйте `.env`. Для остановки используйте `docker compose down`.
**`docker compose down -v` удаляет базу.** Перед обновлением сделайте резервную копию:

```sh
docker compose exec -T db pg_dump -U bashkir -d bashkir > backup.sql
docker compose up --build -d
```

Замените имя пользователя и БД, если изменили их в `.env`. Миграции `db/*.sql`
применяются один раз в транзакциях; история хранится в `schema_migrations`.
Несколько backend-процессов сериализуют миграции advisory lock. Существующая
инсталляция без истории миграций проходит идемпотентные обновления без удаления данных.

## Вход и обучение

Пользователь регистрируется на сайте и выбирает языковую пару. Если при входе
почта не зарегистрирована, в форме остаётся понятное сообщение с предложением
создать аккаунт. Неверный пароль и сбой БД имеют отдельные ошибки.

В «Заданиях» можно подтвердить предложение или написать исправление. За ответ
начисляется 10 XP; цели за 3 и 5 переводов и первое исправление дают дополнительные
награды один раз в день. День рассчитывается по UTC. Один фрагмент в одной паре
не выдаётся пользователю повторно; когда корпус закончится, нужно добавить материалы.
Повтор запроса с тем же idempotencyKey не начисляет XP ещё раз.

Рейтинги доступны по участникам, школам и классам; за день, неделю, месяц, год
и всё время; по XP, заданиям, исправлениям, ошибкам и словарному запасу.
Словарный запас — число уникальных слов исходных фрагментов с правильным ответом
по проверенному эталону или подтверждённому переводу. Это показатель практики,
а не результат лингвистического тестирования. В рейтинг наименьших ошибок входят
только участники с оценёнными ответами. Роли сотрудников исключены из рейтингов.

## Подготовка материалов

Администратор входит с ADMIN_EMAIL / ADMIN_PASSWORD из `.env`.
В «Модерации» доступны:

1. Импорт TXT на башкирском или другом исходном языке: предложения либо абзацы.
   Хранятся исходный текст, автор, лицензия, глава/абзац и точные байтовые координаты.
2. Ручное создание материала и фрагмента.
3. Импорт аудио MP3/WAV/OGG до 20 МБ с расшифровкой WebVTT до 1 МБ.
   Каждая реплика становится фрагментом с таймкодами. Оригинал аудио и расшифровка
   сохраняются в PostgreSQL, аудио воспроизводится в задании с нужного отрезка.
4. В черновике: ввод правильного и заведомо ошибочного перевода →
   «Сохранить проверенные варианты» → «Опубликовать».

Материалы требуют указания лицензии/разрешения; импорт — подтверждения прав.
Распознавание речи не требуется: таймкоды предоставляет WebVTT. Пример:

```vtt
WEBVTT

00:00.000 --> 00:03.000
Һаумыһығыҙ!

00:03.000 --> 00:05.000
Рәхмәт!
```

ИИ — необязательный помощник: задайте AI_API_KEY, AI_API_URL (Chat Completions)
и AI_MODEL. Кнопка генерирует черновики; администратор редактирует и сохраняет
проверенные варианты перед публикацией. Ручной путь работает без ключа и внешней модели.
Материалы должны соответствовать языковой паре; добавление пары не создаёт контент.

## Согласование и экспорт

После пяти независимых участников вариант с поддержкой ≥80% становится confirmed.
Регистр, пробелы, пунктуация и ё/е нормализуются. Семантически равнозначные варианты
объединяет модератор кнопкой «Объединить синонимы»: их голоса суммируются.
Автоматическая модель не объявляет разные формулировки равнозначными без проверки.
Известный ошибочный эталон не подтверждается автоматически даже большинством.

При отсутствии согласия запись имеет статус expert_review и попадает в список
споров. Потеря согласия у ранее подтверждённого перевода исключает его из экспорта.
Решение модератора фиксируется отдельно и не перезаписывается голосованием.
Один пользователь даёт не больше одного голоса на фрагмент/пару: для старых повторных
ответов используется последний. Изменения ответов, XP и согласования транзакционны.

В «Переводах» доступен экспорт JSON/CSV со всеми полями ТЗ: fragment_id, text_ba,
lang_pair, translation, source, confirmed, status. Выгружаются только confirmed;
спорные записи доступны модератору через API. Экспертная организация получает
список через уполномоченного модератора; автоматическая отправка в УФИЦ РАН не требуется.

Демо содержит 12 учебных фрагментов и 24 варианта. Это **не подтверждённый носителями
корпус**: он возникает после работы участников. Приёмочные тесты создают искусственные
голоса только в тестовой БД, их нельзя выдавать за реальную валидацию.

## Школы и классы

Администратор добавляет школы и назначает роли teacher/moderator.
Преподаватель создаёт класс, добавляет существующего ученика по UUID либо
регистрирует нового ученика с начальным паролем прямо в классе.
Преподаватель получает список учеников и отчёт по активности и выполненным заданиям
через интерфейс и `/classes/{id}/reports`. Это REST-интеграция с учебным процессом;
специфические протоколы LTI/SCORM в ТЗ не требуются.

## Telegram

Задайте TELEGRAM_BOT_TOKEN в `.env`, затем перезапустите API.
На сайте: «Профиль» → «Получить код привязки»; отправьте боту `/start КОД` (15 минут).
Команды: `/start`, `/daily`, `/quests`, `/profile`, `/cancel`.
Подтверждение и исправление используют те же сервисы и прогресс, что сайт.
Состояния диалога хранятся в БД; старые кнопки привязаны к своему заданию и не
применяются к новому. Для регистрации без сайта используйте сайт или преподавателя.
Бот использует long polling, публичный webhook не нужен.

## Разработка и проверки

Go 1.23+, Node.js 22+, PostgreSQL 16. Зависимости зафиксированы в go.sum и package-lock.json.

```sh
# Создайте БД; переменные задаются только для вашего окружения.
cd backend
go test ./...
go vet ./...
# DATABASE_URL и JWT_SECRET обязательны; MIGRATIONS_DIR по умолчанию ../db.
go run ./cmd/server
```

В другом терминале:

```sh
cd frontend
npm ci
npm run dev
npm run build
```

Интеграционный тест создаёт отдельную схему в указанной тестовой БД и удаляет её:

```sh
cd backend
TEST_DATABASE_URL='postgres://user:password@localhost:5432/test?sslmode=disable' go test -v ./...
```

`python3 scripts/acceptance.py` проверяет полный API-цикл, синонимы, экспорт,
роли, регистрацию преподавателем, 75 рейтингов и аудио.
**Запускайте только на отдельной чистой тестовой БД** с тестовыми ADMIN_EMAIL
`admin@example.org` и ADMIN_PASSWORD `review-password-123`. Скрипт создаёт тестовые аккаунты.

Архитектура, ограничения и результаты проверок: [docs/architecture.md](docs/architecture.md)
и [docs/verification.md](docs/verification.md). Настоящие Telegram и внешний ИИ требуют
ваших ключей для внешней приёмки. HTTPS и резервное копирование настраиваются на хостинге.

## Разделение слоёв

Backend запускается из `backend/cmd/server`. В `backend/internal/` находятся
отдельные пакеты domain, service, repository/postgres, transport/httpapi,
transport/telegram, security и translation. Сервисы зависят от своих интерфейсов
репозитория и не используют SQL, pgx или Gin. SQL и маппинг результатов находятся
только в PostgreSQL-адаптере. Зависимости создаются в main и передаются конструкторам.

Подробная схема и обязанности пакетов: [docs/architecture.md](docs/architecture.md).
Границы защищены архитектурным тестом; бизнес-логика входа проверяется с подменой
репозитория без БД. Миграции отформатированы без изменения номеров и операций.
